## Disease-aware data and training layout

One shared evidence graph can contain disease nodes, targets, compounds, assays, structures and provenance edges; keep disease-specific evidence, training labels and evaluation splits partitioned by disease. Run the same pipeline contract for each disease, then permit explicitly designed multi-task/shared-parameter experiments with disease identity and leakage controls. Do not merge assay labels or treat shared targets as independent observations without split auditing.

| Disease | Canonical MONDO ID | Data handling |
|---|---|---|
| NSCLC | `MONDO_0005233` | Broad NSCLC parent disease; retain subtype/stage/molecular-context metadata when present. |
| Alzheimer disease | `MONDO_0004975` | Keep disease-level and phenotype/study-specific evidence distinguishable. |
| Type 2 diabetes mellitus | `MONDO_0005148` | Keep T2D separate from type 1, gestational and broad diabetes mellitus. |

The Open Targets GraphQL API accepts MONDO identifiers in its disease ID field. The IDs above use the matching MONDO disease concepts; live API response/name validation remains the first data-phase task. The broad NSCLC concept is not an NSCLC histology-specific target benchmark. [Open Targets API guidance](https://community.opentargets.org/t/how-to-find-targets-associated-with-a-disease-using-the-new-graphql-api-or-google-bigquery/122/1), [NSCLC Mondo record](https://bioportal.bioontology.org/ontologies/MONDO?conceptid=MONDO%3A0005233&p=classes), [Alzheimer disease Open Targets record](https://platform.opentargets.org/disease/MONDO_0004975/associations), [T2D Mondo record](https://bioportal.bioontology.org/ontologies/MONDO?conceptid=MONDO%3A0005148&p=classes).
